# 中断与优先级映射表（irq-map）

> 本文件与 `main.c` 同目录，随代码同仓维护。改 NVIC 配置、加中断、改嘀嗒源时必须在同一次提交里更新本文件。
> 未实测的时间填 `needs-info`，不凭经验估数字。

## 1. 基本信息

| 项目 | 值 |
|---|---|
| 产品／型号 | CIU32L051 LITE-64 核心板 闪灯例程 |
| MCU | CIU32L051x8（Cortex-M0+，Flash 64KB，SRAM 16KB） |
| NVIC 优先级位数 | 2 位（`ciu32l051.h` 中 `__NVIC_PRIO_BITS = 2U`），可用级数 0～3 |
| 优先级分组（PRIGROUP） | 无（Cortex-M0+ 不支持分组） |
| 嘀嗒源与周期 | SysTick，1ms，对应 `SCH_TICK_MS = 1`（CMake `-DSCH_TICK_MS`） |
| 时钟 | HCLK 48MHz，PCLK1 48MHz，PCLK2 48MHz |
| 编译器 | arm-none-eabi-gcc 14.3.1（GNU Tools for STM32 14.3.rel1） |
| 最后更新 | 2026.11.04 |

**编号规则**：数值越小优先级越高。本工程当前只有一个中断源，暂定 3 级；后续新增时按 `0～1` 故障与安全关断、`2～3` 通信收发边沿、`4～5` 时间基准与采样（受 2 位限制，需重新分配）、`6～7` 其余周期任务 的意图分配，实际级数受 2 位优先级限制，最多 4 级。

## 6. 嘀嗒中断内任务（`SCH_MODE_ISR`）

| 任务函数 | 注册周期 | 最坏执行时间 | 为什么必须放中断里 | 超时处理 |
|---|---|---|---|---|
| 无 | - | - | 当前无抢占式任务 | - |

> `SCH_MODE_ISR` 任务的执行时间直接叠加到所有低优先级中断的响应延迟上。凡是最坏执行时间超过 50 µs 的，一律改 `SCH_MODE_COOP` 或 `SCH_MODE_COOP_COALESCE`。

## 7. 分配依据

- 本工程只有 SysTick 一个中断，设为 3 级（最低），便于后续通信中断以 2 级抢占时间基准。
- LED 刷新放在主循环的合作式合并任务里，不进中断：闪烁相位由 `sch_time_ms()` 换算，晚几十毫秒无影响。
